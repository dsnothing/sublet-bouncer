# Decision map

Confidence values are policy annotations, not calibrated correctness probabilities. D5 is computed before D2 but emitted after D4. The `blocking` property distinguishes verdict-blocking questions from informational review notes. Both remain unresolved escalations for the stricter ICS gate.

| ID | Inputs → output | Method and reason | Threshold and escalation | Failure mode | Covering tests |
| --- | --- | --- | --- | --- | --- |
| D1 | Listing → fields with original spans | LLM handles varied wording; offline rules extract locally; verifier rejects unsupported evidence | Below 0.8, missing rent and verifier drops produce non-blocking notes. Missing address and injection indicators block. | A real span can still be misunderstood; invalid schema falls back | `drops a fabricated span and escalates` (core); `low confidence and dropped non-address fields are notes, not HOLDs`; `missing address is blocking, including after typed corrections` (escalation) |
| D2 | Listing, proposals, applicability, rule table → clause findings | Regex rules anchor sections; live proposals require known IDs, real spans, a relevant concept and no negated restriction | Exact 1, fuzzy 0.6, proposal 0.7; below 0.75 asks for review. Non-info rules block; info topics stay ok with non-blocking notes. Proposals never mark clauses void. Void findings downgrade to questionable unless applicability is applies. | Negation/exception errors and missed paraphrases | `D2 violation proposals remain blocking; info proposals remain ok and non-blocking` (escalation); `rejects unrelated proposals and logs the gate outcome` (precision) |
| D3 | Listing features, fields, rent proxy, fixed weights → score/band/contributions | Logistic model makes weighted signals inspectable | Below 0.3 proceed; 0.3–0.7 inclusive creates a blocking question; above 0.7 refuses | Synthetic-only training; score uncalibrated | `is deterministic and shares training/serve feature order` (core) |
| D4 | Address, campus, class time, geocodes and routes → commute | Cached coordinates first; API can obtain missing coordinates from Nominatim; route still comes from bundled schedules | Geocode at least 0.8, origin at most 600m; margin at least 10 minutes feasible, 0–9 tight, negative infeasible. Unknown produces a non-blocking note, never a guessed itinerary, and blocks ICS. | Approximate geocodes/walks; stale schedules; lookup outage | `unknown commute is non-blocking but continues to gate ICS`; `live fallback supplies coordinates but still requires a verified route; errors stay unknown` (escalation) |
| D5 | Listing plus owner field → applies / may_not_apply | Defaults to applies absent residence/sharing evidence. Explicit owner_lives_in=false gives applies; residence/sharing evidence without explicit separate kitchen and bathroom gives may_not_apply. | may_not_apply asks a blocking kitchen/bath question. Display threshold 0.8 does not control the branch. A human correction can set unknown. | Default is a screening assumption; owner residence is an imperfect sharing proxy; other exceptions absent | `defaults RTA to applies and records an information note without a question`; `does not infer residency from a landlord contact or off-site residence`; parameterized owner residence/sharing test (escalation) |
| D6 | Refusal, pre-viewing demands, score, escalations, clauses, commute → verdict/reasons | Rules keep precedence inspectable | Refused input, payment before viewing, detected sensitive identity/banking requests before viewing, or score >0.7 → REFUSE. Blocking questions, non-ok clauses or infeasible commute → HOLD; otherwise ADMIT. Notes alone do not force HOLD. | ADMIT cannot establish authenticity; patterns can miss wording | `admits a clean listing with seven typed decisions` (core); parameterized pre-viewing sensitive request and negation tests (escalation) |
| D7 | Result and profile → action status/tier | Rules enforce narrow capabilities | ICS needs feasible/tight commute, score <0.3, no input refusal and zero unresolved escalations, including non-blocking notes; confirmation required. Refused input blocks reply/copy. | Local capability state is not account authorization | `ICS requires feasible/tight, low risk, and no open questions (including non-blocking)` (escalation); `requires human perform to complete ICS` (core) |
