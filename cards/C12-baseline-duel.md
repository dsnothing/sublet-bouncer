## Part A — Codex (L3)
1. **Pre-register (separate commit, before any baseline call).** Create `evals/baselines/` with:
   - `b1_prompt.txt`, a fair, typical prompt to the same model `gemini-3.1-flash-lite` at temperature 0 with JSON output: "You are helping a university student in Waterloo, Ontario decide whether a sublet listing is safe and legal. Read the listing. Answer ADMIT (looks fine), HOLD (ask questions first) or REFUSE (likely scam or seriously illegal). List each clause you think is illegal under Ontario's Residential Tenancies Act with an exact quote from the listing, the issue category, and the RTA section." Give B1 the same 12 rule titles from `data/rta_rules.json` as allowed categories plus "other". This *helps* the baseline, so disclose it.
   - `b2_checklist.ts`, a deterministic checklist from the RCMP rental-scam advisory (URL from DATA-SOURCES.md:41, with an access date). Flags: payment or deposit before viewing, landlord away or abroad, wire/crypto/gift-card payment, urgency, messaging-app only, no address. REFUSE if ≥ 2 flags, HOLD if 1, ADMIT if 0. No clause detection (report clause metrics as n/a).
   - `PREREG.md` with the SHA-256 of both files, the scoring rules below, the call budget and the statement "run once; no prompt iteration after the first call." Commit this first ("C12: pre-register baselines"). The run commit must come after it.
2. **Harness** `evals/run_baselines_v3.ts` (new file; do not import or modify `run_eval_v3.ts`):
   - Loads the 30 `evals/redteam-v3/*.json` items (inputs and labels only) and the frozen Bouncer rows from `evals/results-v3-final.json`.
   - B1: one call per listing, paced ≥ 9 s, at most 2 retries 30 s apart on 429/503/timeout. Otherwise the row is `no_answer` and counted as wrong; report the count.
   - Raw responses are cached to `evals/cache/baselines-v3/` and a rerun reads only that cache. `--live` is required to make calls, and the harness refuses to call again if the cache is complete.
   - Record `usageMetadata` (prompt, candidates and total tokens) for every B1 call.
3. **Bouncer token cost without touching product code:** run a separate `evals/measure_bouncer_tokens.ts` on 10 **dev** listings (`evals/gold/01-10`, not v3). It wraps `globalThis.fetch` in the script to read `usageMetadata` from the responses of the unmodified `createGeminiAdapter()`, and reports mean and p95 tokens per check. Do not edit `api/gemini.ts`; its hash is recorded in v3.
4. **Scorer** `evals/baseline_score.ts`: a copy of the v3 scoring rules (verdict accuracy, violation rule-ID micro P/R restricted to void/questionable ids, unsafe ADMIT = expected HOLD or REFUSE but got ADMIT). **Parity proof:** a test `tests/baseline-score.test.ts` re-scores the frozen offline and flash-lite rows in `results-v3-final.json` and must reproduce the published headline exactly (offline verdict 0.767, P/R 1.000/0.385; flash-lite verdict 0.800, P/R 0.778/0.538). Two more mechanical counts apply to every system:
   - (a) **Quotes not in the listing**: quote not found after whitespace and case normalisation (use `findSpan` from `core/extract.ts`).
   - (b) **Citation mismatches**: cited section ≠ the `section` of the chosen category's rule in `data/rta_rules.json`.
   Label (b) "section does not match the verified rule section" and never "invented law". A real section outside our table is not proof of fabrication.
5. **Cost:** `evals/baselines/pricing.json` `{model, input_per_1M, output_per_1M, url, accessed}` is supplied by the lead (L8). If it is absent, report tokens only and write "cost not computed". Always say "list-price estimate; the demo runs on the free tier ($0)".
6. **Report:**
   - `evals/RESULTS-BASELINES.md` and `evals/results-v3-baseline.json`, generated by the harness.
   - Header: post-v3 comparison, run date, harness SHA, prereg SHA, "Bouncer rows are the frozen v3 run at 9be1f86, not re-run", n = 30, synthetic data.
   - One table: System | Verdict acc | Violation P/R | Unsafe ADMIT | Quotes not in listing | Section mismatches | no_answer | Tokens per check | List-price cost per check. Rows: B2 checklist, B1 plain chatbot, Bouncer offline (v3), Bouncer live incl. fallbacks (v3).
   - Add Wilson 95% intervals for verdict accuracy (n is small) and a "what this does not show" section.
7. **Toggle data:** after card C10's hero sample is merged, run B1 once on the 3 current `SAMPLE_LISTINGS` with the same prompt (3 calls) and write `web/src/data/baseline-samples.json` with the raw answer, each quote's `inListing` boolean and each section's `matchesRule` boolean, model, and date. Add a test that the stored listings equal the current samples (parity, like capacity.test.ts).
